### 0.3 ⚠️ 扁平棋子夹取策略测试（预估 2-4h）【关键风险】⏸️ 等待小棋子到货

**暂停原因**：当前棋子太大（两枚贴紧时夹爪无法操作），已下单小象棋。

**目的**：中国象棋棋子是扁平圆盘（直径约 3.5cm，厚约 1.5cm），无法像立体棋子从上方直接夹取。需实测确定最优夹取策略。

**测试脚本**：`python3 chess_robot/scripts/test_piece_grasp.py`
- freedrive 拖拽到目标夹取位姿 → 自动闭合夹爪 → 抬升 → 记录结果
- 支持多轮测试，结果自动保存到 `config/grasp_test_results.json`
- 用法：`--rounds N` 指定轮数，`--grip-open N` 指定初始开度

**方案 A — 上方垂直夹取**（需高精度对齐）：
```
1. 夹爪开到略大于棋子直径
2. 垂直降到棋子两侧
3. 闭合夹爪 → 靠摩擦力夹住圆盘边缘
4. 垂直抬升
风险：摩擦力不足则棋子滑落；水平定位不准则碰倒棋子
```

**方案 B — 倾斜侧夹**（推荐先试）：
```
1. 末端倾斜 20°~30°，使下方指尖低于棋子顶面
2. 从侧面滑入，下方指尖托住棋子底部
3. 闭合夹爪，上方指按住棋子顶面
4. 垂直抬升
风险：需要 TCP 姿态倾斜，可能与其他棋子干涉
```

**方案 C — 推滑 + 固定位夹取**：
```
1. 用夹爪侧面把棋子推到棋盘边垫片/凹槽
2. 在预设夹取点夹取
3. 放子时先放到格点附近，再用夹爪拨到位
风险：可能推倒棋子或划伤棋盘
```

**测试步骤**：
1. 桌面上放一颗扁平棋子
2. freedrive 下手动移动夹爪到棋子旁
3. 依次测试方案 A / B / C
4. 记录可行的夹取姿态（TCP 位姿、夹爪开度）
5. 测试放置：夹着棋子放到指定点，松开后棋子不倒
6. **输出**：确定夹取策略，记录夹取/放置参数

**FEN 格式**（中国象棋 Position-FEN）：
- 格式：`<棋盘>/<走子方>/<未吃子步数>`
- 初始 FEN：`rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1`
- UCCI 坐标表示：列 a-i (对应 0-8)，行 0-9 (对应 9-0)

**需要实现的中国象棋规则**：
| 棋子 | 走法 | 限制 |
|------|------|------|
| 帅/将 | 九宫内直走一步 | 行0-2/行7-9，列3-5 |
| 仕/士 | 九宫内斜走一步 | 同上 |
| 相/象 | 田字走法（2×2对角）| 不能过河，塞象眼检测 |
| 馬/马 | 日字走法（1×2 L形）| 蹩马脚检测 |
| 車/车 | 直线任意距离 | 不可越子 |
| 炮/砲 | 直线移动，吃子须翻炮架 | 移动时不翻山，吃子时必须有且仅有一个炮架 |
| 兵/卒 | 未过河只能向前，过河可左右前 | 不可后退 |
| 通用 | 将帅对面（两将之间须至少有一子）| 自动判定 |

**API 设计**：
```python
class ChineseChessEngine:
    def __init__(self, engine_path: str, think_time: float = 1.0)
    def reset(self)                              # 重置到初始局面
    def set_fen(self, fen: str)                  # 从 FEN 设置局面
    def get_fen(self) -> str                     # 获取当前 FEN
    def get_board_state(self) -> list[list[str]] # 10×9 二维数组
    def get_legal_moves(self) -> list[str]       # 所有合法走法 (UCCI)
    def is_legal(self, move_ucci: str) -> bool   # 判断走法是否合法
    def push_move(self, move_ucci: str)          # 执行走法
    def get_best_move(self) -> str               # Pikafish 最佳应手 (UCCI)
    def is_game_over(self) -> tuple[bool, str]   # (是否结束, 结果描述)
    def detect_move(self, before_10x9, after_10x9) -> str  # 从棋盘变化反推走法

    # 辅助
    def ucci_to_human(self, move_ucci: str) -> str   # "b2e2" → "炮二平五"
    def human_to_ucci(self, move_human: str) -> str  # "炮二平五" → "b2e2"
    def shutdown(self)
```

**Pikafish UCCI 通信流程**：
```
启动子进程 pikafish
  ← "ucci"       → 发送 UCCI 初始化
  → "ucciok"     ← Pikafish 确认
  ← "isready"    → 询问就绪
  → "readyok"    ← Pikafish 就绪
  ← "position fen <FEN>"  → 设置局面
  ← "go time 1000"        → 限时思考 1 秒
  → "bestmove b2e2"       ← Pikafish 输出最佳走法
```

### 2.2 `chess_perception.py` — 棋盘感知（预估 4-6h）

**目的**：通过腕部相机识别 9×10 棋盘上 90 个交叉点的棋子占用状态，并检测人类走棋变化。

**API 设计**：
```python
class ChineseChessPerception:
    def __init__(self, camera_topic: str, board_config: dict)
    def detect_board(self, color_image: np.ndarray) -> dict
        # 返回: {"corners": [(x,y)*4], "pose_in_cam": (xyz, quat), "success": bool}
    def compute_intersection_positions(self, board_pose: dict) -> list
        # 返回: 90个交叉点在棋盘坐标系下的 (x, y, z=0)
    def get_intersection_rois(self, color_image, board_pose) -> list
        # 返回: 90个 ROI 区域图像
    def classify_intersections(self, rois) -> list[list[int]]
        # 返回: 10×9 状态矩阵, 0=空 1=红子 2=黑子
    def capture_board_state(self) -> list[list[int]]
        # 完整流程: 拍照 → 检测棋盘 → 90点分类 → 状态矩阵
    def detect_move(self, before_state, after_state) -> dict
        # 对比前后状态 → {"from": (r,c), "to": (r,c), "captured": (r,c)|None, "move_ucci": str}
    def get_board_image(self) -> np.ndarray
        # 获取当前相机图像
```

**90交叉点占用检测算法**：
```
1. cv2.aruco.detectMarkers() → 检测四个 ArUco 角点
2. 根据四个角点的像素坐标 + 已知棋盘行列数，线性插值
   → 计算全部 90 个交叉点的像素坐标
3. 每个交叉点取固定大小 ROI（如 20×20 px）
4. 对 ROI 做 HSV 颜色空间分析：
   - V < 阈值 → 空（交叉点颜色为棋盘底色）
   - 红色 Hue 范围 + S 高 → 红方棋子
   - 黑色/深色（低 V，低 S） → 黑方棋子
   - 空（棋盘底色，中 V，低 S）
5. 返回 10×9 矩阵: 0=空, 1=红子, 2=黑子
```

**走棋检测逻辑**：
```
before: 10×9 矩阵（走棋前）
after:  10×9 矩阵（走棋后）

规则：
- 有一个位置从 占 → 空 (from_position)
- 有一个位置从 空 → 占 (to_position)
- 对于吃子：to 位置原本有对方棋子，但现在换成了己方棋子
  （即 to 位置状态改变 + 某子消失）

返回: {"from": (r1,c1), "to": (r2,c2), "captured": (r,c)|None}
结合 chess_engine.is_legal() 验证走法唯一性
```

### 2.3 `chess_motion.py` — 运动规划（预估 3-4h）

**目的**：将棋盘交叉点坐标映射到机械臂基座坐标系下的 TCP 位姿。

**API 设计**：
```python
class ChineseChessMotion:
    def __init__(self, robot, config: dict)
    def update_board_pose(self, board_pose_in_base: dict)
    def intersection_to_xyz(self, row: int, col: int, height_offset: float = 0.0) -> list
        # 交叉点 → [x, y, z] in base frame
    def pick_piece(self, row: int, col: int) -> bool
        # 从 (row, col) 交叉点取子
    def place_piece(self, row: int, col: int) -> bool
        # 将棋子放到 (row, col) 交叉点
    def remove_captured_piece(self, row: int, col: int) -> bool
        # 吃子：从目标格取走对方棋子，放到弃子区
    def execute_move(self, move_ucci: str) -> bool
        # 完整执行一步走棋（含吃子处理）
    def go_home(self)
    def go_observation_pose(self)
    def go_safe_pose(self)
```

**交叉点→3D坐标映射链**：
```
交叉点 (row=3, col=1) 在棋盘坐标系下:
  board_frame: [col*spacing, row*spacing, 0]  (相对棋盘原点)

棋盘在 camera 系:  ArUco → camera_pose_board
相机在 end-effector 系: ee_cam_xyz, ee_cam_q (手眼标定)
末端在 base 系: robot.getl() (当前末端位姿)

最终: board_point → camera系 → ee系 → base系 = intersection_xyz_in_base
```

**取子动作序列**（基于 Phase 0.3 的夹取策略）：
```
1. go_safe_pose()                           # 抬到安全高度
2. movel to 目标交叉点上方 pre_grasp_height
3. movel to 夹取高度（根据策略调整 TCP 姿态）
4. gripper.grasp_chess_piece()              # 执行夹取
5. movel to 目标交叉点上方 post_grasp_lift  # 抬升
```

**放子动作序列**：
```
1. movel to 目标交叉点上方 pre_grasp_height
2. movel to 放置高度
3. gripper.open()
4. movel to 目标交叉点上方 post_grasp_lift
```

**吃子完整流程**：
```
1. 取走目标格的对方棋子 → 放到弃子区 → 返回
2. 取走己方棋子 → 放到目标格 → 返回
```

## Phase 3: 主程序与游戏状态机（预估 3-4h）

### 3.1 `chess_main.py` — 游戏主循环

**状态机**：
```
        ┌──────────────────────────────────────────────┐
        │                                              │
        ▼                                              │
     INIT → CALIBRATE → OBSERVE → WAIT_PLAYER          │
                                │                      │
                                ▼                      │
                           DETECT_MOVE                 │
                           (拍照+对比+验证)              │
                                │                      │
                     ┌──────────┴──────────┐           │
                     │ 非法走法          合法走法│           │
                     ▼                      ▼           │
              提示用户重走          COMPUTE_AI_RESPONSE   │
                                        │               │
                                        ▼               │
                                   EXECUTE_MOVE          │
                                   (机械臂走棋)           │
                                        │               │
                                        ▼               │
                                    GAME_OVER?          │
                                 ┌──────┴──────┐        │
                                 │ Yes         │ No     │
                                 ▼             │        │
                            SHOW_RESULT        └────────┘
```

**每步详细流程**：
```
1. OBSERVE: 拍照 → capture_board_state() → 记录 board_before
2. WAIT_PLAYER: 提示"请走棋，完成后输入 done"
3. DETECT_MOVE:
   a. 拍照 → capture_board_state() → board_after
   b. perception.detect_move(board_before, board_after) → change
   c. engine.is_legal(change.move_ucci) → 验证合法性
   d. 如非法 → 提示用户，回到 WAIT_PLAYER
4. COMPUTE_AI: engine.get_best_move() → ai_move_ucci
   显示: "AI 应手: 马8进7 (h9g7)"
5. EXECUTE_MOVE:
   a. 是否需要吃子？→ motion.remove_captured_piece()
   b. motion.pick_piece(from_row, from_col)
   c. motion.place_piece(to_row, to_col)
6. 检查 engine.is_game_over()
   → 未结束: 回到 OBSERVE
   → 结束: 显示结果
```

### 4.2 异常处理

| 异常 | 处理 |
|------|------|
| 夹爪空抓（棋子未成功夹起） | 检测夹爪电流/位置 → 重试 1 次 → 仍失败则报警暂停 |
| ArUco 检测失败 | 提示用户：调整光照或棋盘位置，输入 retry 重试 |
| 走棋检测不确定 | 多个可能走法 → 列出候选，让用户手动选择 |
| 无法确定走法 | 提示用户手动输入 UCCI 走法（如 "b2e2"） |
| 非法走法（人类走错） | 提示用户重新走棋 |
| 目标位超出工作半径 | 提示用户调整棋盘位置 |
| 机械臂运动中用户急停 | 检测 robotMode 变化 → 暂停游戏，等待恢复 |

### 4.3 中国象棋特殊规则（需在 engine 中覆盖）

| 规则 | 实现要点 |
|------|----------|
| 九宫限制 | 帅/仕的行列范围检查：红方 0-2行 3-5列，黑方 7-9行 3-5列 |
| 塞象眼 | 田字中心点 (r+1,c+1)/(r-1,c-1)... 是否被占用 |
| 蹩马脚 | 马移动方向的第一个邻格是否被占用 |
| 炮翻山 | 移动（不翻山），吃子（必须翻且仅翻一个炮架/炮墩） |
| 将帅对面 | 两将所在列之间无任何棋子时非法 |
| 困毙 | 无合法走法时判负（不同于国际象棋的 stalemate 和棋） |
